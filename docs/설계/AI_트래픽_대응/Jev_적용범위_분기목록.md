## 0. 결론 먼저

- **Jev(또는 이미 쌓인 Jev 태그)로 바꿀 가치가 큰 곳 3곳**: ① 동적 다음 질문(`/api/next-question`, 입력이 가장 큼) ② 공고 자격조건 구조화(LLM) 중 "대상 여부" 부분 ③ 근무지·소재지의 시도 판정. 모두 **"수집 때 공고당 1회 Jev → 태그 저장, 대화 때는 코드 계산"** 구조다. 대화 턴마다 Jev를 부르지 않는다.
- **추가 후보 3곳**: 고령·특수대상 전용 판정(`notForYouth`·`targetCheck` 경고), 신청 준비 유형(`prepKind`), 경력직 전용 판정. 정규식 오판이 보이는 곳이다. **단, 공짜가 아니다**: 지금 `jevState`는 제목 160자·기관 60자·요약 400자만 보내므로 자격요건·신청방법·근무지 문장을 상태에 추가해야 하고(입력 토큰 증가), 묶음은 최대 12문항(`MAX_QUESTIONS`)이라 질문을 늘리면 정확도 저하 여부도 검증해야 한다.
- **절감률·비용은 아직 산정 불가**: 경로별 실제 호출 수·입출력 토큰·캐시 적중률 기준선이 없다. 아래 표의 "예상 절감"은 방향일 뿐 수치 약속이 아니다.
- **바꾸면 안 되는 곳**: 나이·소득·날짜·마감 비교(엔진 판정, `targetCheck` 차단, 변경 감지), 출력 검증기(`validateQuestion`·`checkDraft` 등), 출처별 고정 매핑, 법령 근거 조건. Jev는 산술·날짜에 약하고 비결정적이며, 이 분기들은 설명 가능하고 재현돼야 한다.
- **글쓰기는 Jev 불가**: 공고 쉬운 요약, 신청 준비 초안, 질문 문장 다듬기. 다만 질문 문장 다듬기는 Jev가 아니라 **템플릿만 쓰고 LLM 호출 자체를 끄는 것**이 맞다.

## 3. 적용 우선순위 (승인 시, 분류 DB 스레드 완료 후)

| 순서 | 대상 | 이유 | 선행 조건 |
|---|---|---|---|
| 1 | **L1 동적 다음 질문** → 태그 분포 기반 축 선택 + 템플릿/승격 풀, LLM은 새 축만 | 턴마다 1만+ 토큰, 가장 많이 불림. Jev 호출 추가 없이 이미 쌓인 태그만 씀 | 태그가 DB에 저장돼 대화 시점에 읽힐 것(다른 스레드) |
| 2 | **L3 자격조건 대상 noul + R5 주 대상 choice** 를 L9 묶음에 추가 | 공고당 1회. 규칙·캐시 이후 남는 LLM 구조화 호출을 대체 | `jevState`에 자격요건 원문 추가, 정답셋 100건 이상으로 축별 정확도 확인 |
| 3 | **R7 경력직, R11 신청 유형·방법** 묶음에 추가 | 오탈락·템플릿 오선택 감소(제외·탈락에는 아직 안 씀) | 2와 같음 |
| 4 | **L4 시도/시군구 choice** | 지역 필터·핀 품질. 상세 주소는 LLM 유지 | 채용 "근무지 문장 근거" 원칙 유지 테스트 |
| 5 | **L7 질문 다듬기 호출 끄기** (Jev 아님) | 노출당 호출 제거 | 템플릿 문체 점검 |

비용·절감률은 **현재 산정 불가**. 먼저 공급자 usage 집계(`bfc9056`에서 추가)로 경로별 호출 수·입출력 토큰·캐시 적중률 기준선을 잡고, 적용 후 `.ai-sync/compare/` before/after로 비교해 기입한다. 참고로 Jev 단가는 입력 100만 토큰 $0.042·출력 무료라 Jev 쪽 비용은 LLM 대비 작지만, 상태에 원문 필드를 늘리면 공고당 입력이 커진다.

## 4. 공통 위험과 원칙

1. **숫자·날짜·금액은 Jev 금지** (R1·R12·R13·R17). 실측에서도 나이 판단 0.51.
2. **오탈락 방지 원칙 유지**: Jev 결과로 공고를 "제외·탈락"시키는 분기(R5 제외, R7 경력 필수, L3 대상 조건)는 확신도 0.9 이상 + 원문 근거 단어 검사(R3)를 함께 통과할 때만. 그 외는 `low` → 엔진에서 "확인 필요".
3. **묶음 질문이 늘면 정확도가 떨어질 수 있음**(검증 안 됨). 현재 상한 12문항. 늘리거나 별도 묶음으로 나누기 전에 정답셋 정확도 비교.
3-1. **필요한 원문이 상태에 없음**: L3·R5·R7·R11·R26은 자격요건·신청방법·근무지 문장이 필요하다. `jevState` 확장 시 토큰·잡음 증가를 같이 측정.
4. **단일 업체 의존**: Jev 장애 시 `askJev`는 null → 기존 규칙·LLM으로 폴백되는 현재 구조 유지. 모델 버전 `JEV_MODEL` 고정, 올릴 때 정답셋 재측정.
5. **정확도 근거가 아직 없음**: 현재는 표본 육안 비교와 3건 실측뿐. 심사·발표에서 "AI 분류 정확도"를 말하려면 정답셋 측정이 먼저다.
6. **충돌 주의**: `lib/sources/classify.ts`·`lib/sources/index.ts`·`lib/server/pool.ts`는 지금 다른 스레드가 수정 중. 이 문서의 2~4순위는 그 스레드 완료 후 같은 파일에 질문만 추가하는 형태로 진행한다.
