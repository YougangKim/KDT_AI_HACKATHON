# 공고 "쉬운 요약"을 대화형 무료 AI 없이 만드는 방법 검토

> Codex 교차 검토(`.ai-sync/tasks/20261124T112255-codex/result.md`, 조건부) 반영: 실패율 일반화·4초 설명·공급자 목록 정정, 서울시 채용 추가, "위험 없음"과 "고정 문구로 신청방법 보완" 철회, B는 보류로 변경.
> 작성 2026-11-24 Claude · 조사·설계만, 코드 미수정. 근거: `web/lib/ai/summary.ts`, `web/app/api/summary/route.ts`, 로컬 캐시 `web/.cache/ai-summary.json`, 로컬 공고 DB `web/.cache/pool-v1.json`(7,923건)

## 1. 지금 방식과 문제

- 결과 화면에 공고가 보일 때마다 `/api/summary`가 공고 최대 5건을 대화형 AI 체인(Groq→OpenRouter→Cloudflare→Gemini→Anthropic 순, 앞쪽은 무료 등급)에 보내 "무엇을 지원하는지"(40자)와 "신청할 때 할 일" 두 문장을 만든다. 4초 안에 안 오면 화면은 기다리지 않는다(호출 자체는 취소되지 않고 뒤에서 계속돼 캐시에 기록될 수 있음).
- 입력: 공고마다 제목·기관·요약·자격요건 원문·신청방법(JSON). 출력 상한 600토큰.
- **실측(로컬 캐시 61건): 성공 9건, 실패 52건(85%).** 특정 시점 캐시 표본이라 전체 운영 실패율로 일반화할 수는 없다. 실패(`false`)에는 호출 실패·JSON 파싱·길이·말투 검사 탈락이 섞여 있고 사유는 기록되지 않는다. 실패는 하루 뒤 다시 시도하므로 같은 공고에 토큰을 반복해서 쓴다.
- **성공한 결과도 원본 필드를 다시 쓴 수준이다.**
  - AI: "국립중앙의료원에서 서울 근무 계약직 주말약사 1명을 채용합니다." / "기관 채용 사이트에서 지원서를 접수합니다."
  - 원본: 기관 `국립중앙의료원`, 요약 `계약직 / … / 근무지 서울 / 1명`, 신청방법 `기관 채용 사이트에서 지원서 접수`
- 성공 9건 중 채용 공고는 대체로 원본 재서술이고, 정부24 공고는 긴 문장을 축약·정리한 경우도 있다. 결론: **상당 부분은 원본 필드로 만들 수 있는 문장에 생성형 AI를 쓰고 있다.** 다만 사용자가 체감하는 품질 차이는 비교해 봐야 안다.

## 4. 추천

1. **요약은 A(규칙 템플릿)로 바꾸고 `/api/summary`의 AI 호출을 끈다.** 단, 출처별 틀과 빈 칸 규칙을 먼저 만들고 출처별 표본 20건씩 지금 AI 요약과 나란히 비교해 확인한 뒤 바꾼다. 신청방법이 없는 출처는 "원문에서 신청 방법 확인"으로 둔다.
2. B(Jev 문장 고르기)는 설계·품질 검증 후에 다시 판단한다.
3. 대화형 무료 AI는 "문장을 새로 써야만 하는 곳"(신청 준비 초안, 템플릿 없는 새 질문)에만 남긴다.

## 5. 확인할 것 / 위험

- 템플릿 문장 품질은 출처별 표본 20건씩 육안 확인(어색한 조사·빈 칸).
- 원본 요약이 이미 길거나 문장형이 아닌 출처(서울시 채용 등)는 잘라 쓰는 규칙 필요.
- 결과 카드에서 "AI 요약" 표기를 쓰고 있다면 "공고 정보 요약"으로 바꿔야 사실과 맞다.
