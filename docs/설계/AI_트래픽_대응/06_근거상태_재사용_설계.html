무료 AI 결과를 근거와 함께 쌓고, Jev로 재사용하는 구조

적용 설계 요약 · 2026-11-24 · 승인 요청 범위 = 1단계

이미 됨 무료 AI 조사 스레드

  • 칼럼 저장: 공고마다 직무·고용형태 등 tags 칼럼, 수집 때 1회 Jev
  • 빈 칼럼만 Jev에 묻기, 새 질문은 새 칼럼으로
  • 입력 바뀌면 재분류(제목·기관·요약 비교)
  • 추가 질문은 칼럼으로 나뉘면 LLM 없이

초안 반려 Codex 교차 검토

  • Jev가 LLM 호출을 건너뛰게 하면 지역·학력·고용 조건이 빠짐
  • → 대상 아닌 공고가 "바로 신청"으로 통과
  • status 필드는 엔진이 안 읽음 → 기존 confidence 사용
  • 그래서 먼저 측정, 나중에 적용으로 축소

1단계: 수집할 때 공고 1건이 거치는 길

① 어댑터
출처 API에서 공고와 자격요건 원문을 받음(원문은 메모리)
→
② 규칙
나이·소득 숫자, 무주택 등 대상 단어
→
③ 캐시 확인 (수정)
키 = id + 프롬프트 버전 + 원문 해시
원문 바뀌면 다시 계산
→
④ LLM
규칙이 부족할 때만(지금과 같음)
→
⑤ 근거 대조 (추가)
LLM 근거 구절이 원문에 없으면 → "확인 필요"(탈락 X)
→
⑥ 공고 DB 저장
대화 중엔 읽기만
⑦ Jev 관찰 모드 (추가 · 기본 OFF · 결과에 영향 없음)
원문에 Jev 예/아니오 1회: 무주택·1인가구·대학생·구직자·재직자·신혼·수급자·청약통장 + "나이 제한 있음?"·"소득 기준 있음?" → 저장만 하고 비교 스크립트로 측정: 일치율 · 줄일 수 있었던 LLM 호출 수 · 빠졌을 조건 수
지금과 같음 이번에 수정·추가 관찰만(반영 안 함)

1단계 · 승인 요청 안전장치 + 측정

  • 캐시 stale 구멍 막기
  • 지어낸 근거로 탈락시키지 않기
  • Jev로 바꿔도 되는지 실제 공고로 측정
  • 토큰은 아직 그대로(측정 단계)

2단계 · 측정 후 별도 승인 토큰 줄이기

  • 일치율 높은 대상만 Jev로 판정 → LLM 호출 생략
  • Jev만 찾은 조건은 "확인 필요"로 추가
  • 전/후 "바로 신청"·오탈락 비교, 회귀 없을 때만

하지 않음 이유

  • 요청마다 Jev 충분성 판정: 키 조회로 충분, 지연만 늘어남
  • 범용 지식 테이블·임베딩: 대상이 공고 하나
  • 원문 전체 DB 저장: 저장량·비용 미계산
  • classify.ts·pool.ts·엔진: 건드리지 않음
