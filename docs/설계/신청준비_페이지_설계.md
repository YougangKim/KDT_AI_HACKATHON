## 0. 지금 무엇이 문제인가 (공고 "중장년 취업이음+ 면접 공동행사" 사례)

| 현재 화면 | 원인(코드) | 사용자가 느끼는 것 |
|---|---|---|
| 내 조건과 비교 = "분야: 채용·인턴(채용·인턴 정보가 필요합니까? → 예)" 한 줄 | `fit = m.reasons` 를 그대로 씀. reasons는 엔진의 통과 근거라 **취향 조건(interest)** 까지 섞이고, 질문 원문이 괄호로 붙음 | "비교한 게 없다" |
| 중장년 대상인데 아무 경고 없음 | `notForYouth()` 가 housing·benefit만 거르고 job은 통과. 준비 화면엔 대상 검사가 없음 | 대상이 아닌 행사를 준비하게 됨 |
| 체크리스트 = 이력서·자기소개서·졸업증명서 | `BASE_DOCS.job` 고정. **행사형 공고**(면접회·박람회)를 일반 채용과 구분 안 함 | 공고와 상관없는 서류 목록 |
| 신청 순서 = "원문에서 다시 확인 → 서류 준비 → 신청 → 마감 확인" | 모든 공고 같은 4줄 | 정보가 0 |
| 초안 "제 상황(지금 서울에 살고 있습니까?, 채용·인턴 정보가 필요합니까?, …)과 잘 맞는다고 판단했습니다" | `answers.filter(yes).map(question.text)` 로 **질문 문장을 그대로** 끼움 | 어색하고 내용이 없음, 그대로 못 씀 |
| AI 프롬프트에도 `질문 → 예` 원문 전달 | `/api/prep` 가 같은 원문을 보냄 | AI도 같은 실수를 할 여지 |

핵심 원칙 세 가지로 고친다.
1. **대상 먼저**: 이 공고가 나에게 해당되는지부터 말한다. 아니면 준비를 시키지 않는다.
2. **답은 질문이 아니라 사실로**: 인터뷰 기록(attr·op·value·answer)에서 "내 프로필"을 만들고, 그 프로필을 문장으로 바꾼다. 질문 원문은 화면·초안 어디에도 쓰지 않는다.
3. **공고 유형별로 다르게**: 채용 / 채용 행사 / 지원금 / 주거 / 국비 / 자격증 / 알바는 서류·순서·초안이 다르다. 공통 문장은 마지막 수단이다.

## 1. 화면 구성 (위→아래 순서)

```
┌ 상단바: ← 결과로 ·············· [전체 복사] [인쇄·PDF]
├ ① 공고 헤더 카드         제목·기관·분야칩·유형칩 / 마감 D-day / 장소·거리
├ ② 대상 판정 배너         ✅ 신청 가능 · ⚠ 확인 필요 · ⛔ 대상 아닐 가능성 높음 (1줄 결론 + 근거 1줄)
├ ③ 내 조건과 비교 표       공고 조건 | 내 답(자연어) | 판정   ※ 자격 조건만
│     └ 접힘: "내가 찾던 것과 맞는 점" (취향 조건: 분야·직무·지원 종류)
├ ④ 이 공고 한눈에          무엇을 주나 / 언제 / 어디서 / 어떻게 신청  (원문 필드, 없으면 "원문 확인")
├ ⑤ 준비 체크리스트         [공고 명시] [보통 필요] [내 상황 때문에] 3묶음, 진행률 n/m
├ ⑥ 신청 순서(날짜 계산)    오늘 → D-n 준비 → 접수 → (행사일/발표일)
├ ⑦ 작성 초안               유형별 1~2개, [빈칸] 안내, 복사 버튼, AI/기본 표시
└ 하단 고정 CTA            "원문에서 신청하기 ↗"  (⛔일 때는 "원문에서 대상 확인하기 ↗")
```

순서 근거: 사용자는 "내가 되나?" → "뭘 주나?" → "뭘 챙기나?" → "언제까지?" → "뭐라고 쓰나?" 순으로 판단한다. 지금 화면은 ②④가 없어 판단 근거 없이 체크리스트부터 나온다.

### 섹션별 정보와 데이터 출처

| 섹션 | 표시 항목 | 데이터 출처 | 없을 때 |
|---|---|---|---|
| ① 헤더 | 제목, 기관, 분야 칩(`DOMAIN_META`), **유형 칩**(§3 판별), 마감·D-day, 장소, 내 위치 거리 | `o.title` `o.org` `o.domain` `o.applyEnd` `o.place` `o.geo` + `lastResult.location` | 마감 없음 → "상시 접수(예산 소진 시 조기 마감 가능)" |
| ② 대상 판정 | 결론 1줄 + 근거 1줄 + (⛔/⚠) "비슷한 청년 대상 공고 보기" | §5 대상 검사(`o.title` `o.summary` `o.conditions` × 프로필) + `m.status` | — |
| ③ 비교 표 | 공고 조건 원문(짧게) / 내 답 자연어 / 판정 아이콘 | `o.conditions` 중 **자격 attr만**(age, region, homeless, livingAlone, incomePct, employment, subscription, married, welfare, experienced, education) × 프로필(§4) | 자격 조건 0개 → "공고에 나이·지역·소득 같은 자격 조건이 적혀 있지 않습니다. 원문의 '참여 대상'을 확인하세요." (빈 표 금지) |
| ③-접힘 | 내가 찾던 것과 맞는 점 | 취향 attr(interest, field, need, housingKind, topic) | 없으면 숨김 |
| ④ 한눈에 | 무엇(지원 내용) / 언제(접수기간·행사일) / 어디서 / 어떻게 | `o.summary`(문장 분리 후 지원 내용 키워드 문장 1개), `o.applyStart~applyEnd`, `o.place`, `o.apply.how/where` | 항목별 "원문 확인" 회색 표시. 지어내지 않음 |
| ⑤ 체크리스트 | 서류·준비물, 출처 배지 | (a) `docsFromText(summary+rawText)` → [공고 명시] (b) 유형 기본표(§3) → [보통 필요] (c) 프로필 조건부(§3) → [내 상황 때문에] | (a) 0개면 상단에 "공고에 제출 서류가 적혀 있지 않아 일반적인 목록입니다" |
| ⑥ 순서 | 날짜가 박힌 단계 | 유형별 단계 템플릿(§3) + `applyEnd` 로 역산 | 상시 → 날짜 대신 "이번 주 안" |
| ⑦ 초안 | 유형별 초안, 빈칸, 복사 | §6 규칙 초안 → `/api/prep` AI 개선(검사 통과 시만 교체) | 초안이 필요 없는 유형(주거 대부분) → "이 공고는 보통 자기소개서를 받지 않습니다" + 필요 시 펼치기 |
| CTA | 원문 신청 | `o.apply.url ?? o.url` | — |

> 체크박스 상태는 `localStorage`(`prep:<id>`)에 저장해 다시 열어도 유지. 서버 저장 안 함.

## 2. 공고 유형 판별 (domain + 제목 키워드)

`domain` 만으로는 부족하다(면접회도 job). 아래 순서로 첫 번째 일치를 유형으로 쓴다.

| 유형(kind) | 조건 | 예 |
|---|---|---|
| `job_event` 채용 행사 | domain=job·parttime 이고 제목에 `박람회|채용행사|공동행사|면접회|면접 공동|매칭데이|채용설명회|잡페어|일자리 페스티벌` | 중장년 취업이음+ 면접 공동행사 |
| `job` 채용 | domain=job | ○○공사 2026 청년인턴 |
| `parttime` 알바 | domain=parttime | 편의점 주말 |
| `benefit_cash` 지원금 | domain=benefit 이고 `수당|지원금|장려금|바우처|급여|이자|대출` | 청년구직활동지원금 |
| `benefit_service` 지원 서비스 | 나머지 benefit | 청년 마음건강 상담 |
| `housing_rent` 임대 | domain=housing, `housingKind`≠sale | 행복주택, 매입임대 |
| `housing_sale` 분양 | domain=housing, 분양·청약 | 공공분양 |
| `training` 국비 | domain=training | K-디지털 트레이닝 |
| `exam` 자격증 | domain=exam | 정보처리기사 |

## 3. 유형별 체크리스트·순서·초안 차이

[공고 명시] 서류는 항상 맨 위. 아래는 [보통 필요]·[내 상황 때문에] 기본값이다. 기본 목록은 **유형당 최대 5개**(지금 8개는 많다).

| 유형 | [보통 필요] | [내 상황 때문에] (프로필 조건) | 신청 순서 템플릿 | 초안 |
|---|---|---|---|---|
| 채용 | 이력서, 자기소개서(공고 문항 확인), 최종학력 증명서 | 경력 없음 → "경험 정리표(알바·프로젝트)" / 학생 → "졸업예정증명서" | ① 직무·우대사항 확인 ② 자기소개서 문항 확인 ③ 서류 작성(마감 3일 전 완료) ④ 온라인 접수 ⑤ 접수 완료 메일·문자 확인 | **지원 동기** + **강점 3줄 요약** |
| 채용 행사 | 사전 참가신청 여부, 이력서 출력본 3~5부, 일시·장소·준비물 | 거리 30km↑ → "이동 시간 확인" | ① 참가 대상·사전신청 확인 ② 사전신청(마감일) ③ 참여 기업 목록 보고 2~3곳 고르기 ④ 이력서 출력 ⑤ 행사 당일 | **30초 자기소개** + **현장에서 물어볼 질문 3개** (지원 동기 아님) |
| 알바 | 간단 이력서, 근무 가능 요일·시간 | 학생 → 시간표 | ① 근무 조건(시급·시간) 확인 ② 연락·지원 ③ 면접 일정 | **지원 메시지 3문장**(가능 시간 중심) |
| 지원금 | 신분증, 통장 사본, 소득 증빙 | 소득 답 있음 → "건강보험료 납부확인서" / 구직 중 → "구직활동 계획(양식 확인)" | ① 자격(나이·소득) 확인 ② 서류 발급(정부24) ③ 온라인 신청 ④ 심사·결과 발표 확인 | **신청 사유** + **활용 계획** |
| 지원 서비스 | 신분증 | — | ① 대상 확인 ② 신청 ③ 안내 연락 | 사유 1~2문장(선택) |
| 임대 주거 | 주민등록등본, 가족관계증명서, 소득·자산 증빙 | 무주택 예 → "무주택 확인" / 청약통장 예 → "청약통장 가입확인서" / 1인 가구 → 등본 세대 구성 확인 | ① 공급 단지·자격 확인 ② 청약 신청(인터넷) ③ 서류 제출 대상자 발표 ④ 서류 제출 ⑤ 당첨 발표·계약 | 기본 없음("보통 자기소개서 불필요"), 펼치면 **거주 사유** |
| 분양 | 청약통장, 등본, 가족관계증명서 | 청약통장 아니오 → ⚠ "청약통장 없으면 신청 불가일 수 있음"을 ②로 올림 | ① 청약 자격·가점 확인 ② 청약홈 신청 ③ 당첨 발표 ④ 계약 | 없음 |
| 국비 | 국민내일배움카드, 신분증 | 카드 여부 모름 → "카드 발급 2~3주 소요" 강조 | ① 카드 확인/발급 ② 훈련기관 상담 ③ 수강 신청 ④ 선발 면접(있으면) | **수강 동기** + **수료 후 계획** |
| 자격증 | 응시원서, 증명사진, 응시료 | 학력 답 → 응시 자격 증빙 | ① 응시 자격 확인 ② 원서 접수 ③ 수험표 출력 ④ 시험일 | 없음 |

날짜 역산 규칙: 마감 D-n 에서 "서류 준비"는 `max(오늘, 마감-3일)`, 공문서 발급이 필요한 유형(주거·지원금)은 `마감-5일`. 이미 지났으면 "오늘 바로". 행사형은 행사일(`applyStart` 또는 요약의 날짜)을 별도 줄로.

## 4. 인터뷰 답 → 자연스러운 문장 변환 규칙

### 4-1. 두 단계: 답 기록 → 프로필 → 문장
1. `answers`(AttrKey·op·value·answer)를 attr별로 묶어 **프로필**을 만든다. 숫자는 `numericRange`(`lib/engine/answer-groups.ts`)로 구간을 구한다.
   예: age lte 34 예, age lte 29 아니오 → `age: [30, 34]`.
2. 프로필 값을 아래 표의 문장으로 바꾼다. **`question.text` 는 절대 쓰지 않는다.**
3. "모름"은 문장으로 만들지 않는다. 비교 표에서만 "답하지 않음"으로 보인다.

### 4-2. 변환 표 (비교 표용 짧은 말 / 초안용 문장)

| attr | 프로필 | 비교 표 "내 답" | 초안 문장(습니다체) | 초안 사용 |
|---|---|---|---|---|
| age | [30,34] | 만 30~34세 | 만 30대 초반입니다 | 자격 조건에 나이가 있을 때만 |
| region | 서울 | 서울 거주 | 서울에 살고 있습니다 | 공고 지역이 있을 때만 |
| employment | jobseeker | 구직 중 | 현재 일자리를 찾고 있습니다 | 채용·지원금·국비 |
| employment | student | 학생 | 졸업을 앞두고 있습니다 / 재학 중입니다 | 채용·국비 |
| homeless | true | 무주택 | 제 명의의 집이 없습니다 | 주거 |
| livingAlone | true | 1인 가구 | 혼자 살고 있습니다 | 주거·지원금 |
| incomePct | ≤60 | 기준중위소득 60% 이하 | 가구 소득이 기준중위소득 60% 이하입니다 | 지원금·주거 |
| subscription | true | 청약통장 있음 | 청약통장에 가입해 있습니다 | 주거 |
| education | 3 | 대졸 | 4년제 대학을 졸업했습니다 | 채용 |
| experienced | false | 관련 경력 없음 | 이 분야는 처음 도전합니다 | 채용(신입 맥락으로만) |
| field | 정보통신 | (취향) 정보통신 희망 | 정보통신 분야에서 일하고 싶습니다 | 채용·국비 |
| need | 생활비 | (취향) 생활비 지원 필요 | 생활비 부담을 덜고자 합니다 | 지원금 |
| interest | job | (취향) 채용 정보 찾는 중 | **쓰지 않음** | 쓰지 않음 |
| region 아니오만 있음 | ≠서울 | 서울 외 거주 | 쓰지 않음(부정 사실은 초안에 넣지 않음) | — |

### 4-3. 문장 조립 규칙
- 초안 1개에 상황 문장은 **최대 2개**. 공고 `conditions` 에 있는 attr 를 먼저, 그다음 유형 관련 attr.
- 두 문장은 접속으로 잇는다: "현재 일자리를 찾고 있으며, 4년제 대학을 졸업했습니다."
- 금지: 물음표, "~입니까/~습니까?", "예/아니오", 괄호 안 나열, "제 상황(…)", "인터뷰 답변", "판단했습니다" 같은 빈 말.
- 부정 답(아니오)은 초안에 쓰지 않는다. 비교 표에만 보인다.
- 사실이 하나도 없으면 상황 문장 없이 [빈칸]으로 둔다("[지금 상황: 예) 졸업 후 6개월째 구직 중]").

### 4-4. 좋은 예 / 나쁜 예

| 구분 | 문장 | 이유 |
|---|---|---|
| 나쁨 | 제 상황(지금 서울에 살고 있습니까?, 채용·인턴 정보가 필요합니까?, 알바 정보가 필요합니까?)과 잘 맞는다고 판단했습니다. | 질문 원문, 취향 조건, 근거 없는 판단 |
| 좋음 | 서울에 살며 졸업 후 일자리를 찾고 있어, 서울 근무로 바로 시작할 수 있는 이번 인턴 공고에 지원합니다. | 사실 2개 + 공고와 연결 |
| 나쁨 | 현재 인터뷰에서 답한 상황이며, 이 지원으로 생활 안정에 도움을 받고자 합니다. | 빈 말 |
| 좋음 | 혼자 살며 가구 소득이 기준중위소득 60% 이하라, 월세 부담을 줄이기 위해 청년월세 지원을 신청합니다. [월세 금액: 예) 월 45만 원] | 자격 사실 + 공고 혜택 + 구체 빈칸 |
| 나쁨 | 맡은 업무를 빠르게 익혀 기여하겠습니다. | 누구나 쓰는 문장, 공고 정보 0 |
| 좋음 | 공고의 '데이터 정리·보고서 작성' 업무에 맞춰, [관련 경험: 예) 학과 프로젝트에서 설문 300건 분석]을 살려 첫 3개월 안에 정기 보고 업무를 맡겠습니다. | 공고 업무 인용 + 경험 빈칸 + 구체 계획 |
| 나쁨 | 공고에서 요구하는 역할에 관심이 있습니다. | 어떤 역할인지 없음 |

## 5. 대상이 안 맞는 공고 경고 (예: 중장년 행사)

### 5-1. 검사 규칙 (`targetCheck(o, profile)` → ok / warn / block)

| 신호 | 판정 | 근거 표시 |
|---|---|---|
| `conditions` 에 age gte N 이고 프로필 나이 상한 < N | **block** ⛔ | "공고 조건 '만 40세 이상', 내 답 만 30~34세" |
| 제목·요약에 `중장년|신중년|장년|고령자|노인|어르신|시니어|50\+|5060|4050` 이고 `청년` 없음 | **warn** ⚠ (나이 답이 39세 이하면 문구 강화) | "제목에 '중장년'이 있어 만 40세 이상 대상일 가능성이 큽니다" |
| `경력단절|북한이탈|장애인 전용|보훈|외국인|다문화|한부모` 가 제목에 있고 프로필에 근거 없음 | warn | "특정 대상 전용 공고로 보입니다" |
| 프로필 region 과 `o.region` 이 다름 | block | (지금 엔진이 이미 탈락시킴, 방어용) |
| `m.status = needs_check` | warn(약) | "확인할 조건 n개" |
| 그 외 | ok ✅ | "답한 조건 기준으로 신청 가능합니다" |

### 5-2. 화면 동작
- **block**: ② 배너 빨강. 체크리스트·순서는 접힌 채 보이고, **초안은 만들지 않는다**(AI 호출도 안 함 → 비용·오해 방지). CTA 문구 "원문에서 대상 확인하기 ↗". 배너 아래 "비슷한 청년 대상 {분야} 공고 보기" 링크(`/result?domain=`).
- **warn**: ② 배너 주황. 모든 섹션 보이되, 초안 영역 위에 "대상 확인 후 쓰세요" 안내. AI 초안은 사용자가 "그래도 초안 만들기" 를 누를 때만 호출.
- **ok**: 초록 한 줄, 공간 최소.
- 문구 예(중장년 행사, 나이 답 만 25~29세):
  > ⚠ **대상이 아닐 수 있습니다.** 제목에 '중장년'이 있어 보통 만 40세 이상(또는 50세 이상) 구직자 대상입니다. 원문의 '참여 대상'을 먼저 확인하세요.
- 결과 목록 쪽 개선(별도 작업 제안): `notForYouth()` 를 job·training 에도 적용하되 "채용 공고(직원 모집)" 와 "중장년 참여 행사" 를 구분 — 제목에 행사 키워드가 있을 때만 제외/경고.

## 6. 초안 생성: 규칙 기본 초안과 AI

### 6-1. 유형별 기본 초안 틀 (AI 실패 시 그대로 노출)
`{ }` = 데이터로 채움, `[ ]` = 사용자가 채울 빈칸(예시 포함).

**채용 · 지원 동기**
> {org}의 「{title}」에 지원합니다. {상황 문장 1~2개, 공고와 연결}. 특히 공고의 '{업무 키워드 or [관심 업무]}' 업무에 [관련 경험: 예) 카페 아르바이트 1년 동안 재고·발주 관리]을 살릴 수 있다고 생각합니다. 입사 후에는 [첫 6개월 목표: 예) 업무 매뉴얼을 익혀 정기 보고서를 혼자 작성]하겠습니다.

**채용 · 강점 3줄** — "· [강점 1: 경험/수치]" ×3, 맨 위에 "공고 우대사항: {원문 우대 문장 or '원문 확인'}".

**채용 행사 · 30초 자기소개**
> 안녕하세요, [이름]입니다. {상황 문장 1개}. [희망 직무]에 관심이 있고, [관련 경험 한 가지]을 해 왔습니다. 오늘 {org} 행사에서 [관심 기업 유형]의 채용 계획을 듣고 싶어 참여했습니다.

**채용 행사 · 현장 질문 3개** — "이 직무에 신입(또는 경력 n년 미만)도 지원할 수 있습니까?" / "채용 일정과 다음 전형은 어떻게 됩니까?" / "현장 면접 후 결과는 언제 알 수 있습니까?" (일반형, 공고 무관해도 유효)

**지원금 · 신청 사유**
> {상황 문장 1~2개(소득·가구·구직)}. 「{title}」의 {지원 내용 or [지원 내용]}을 받아 [쓸 곳: 예) 월세 45만 원 중 일부]에 쓰고자 신청합니다.

**지원금 · 활용 계획** — "[1개월 차: …] / [3개월 차: …]" 2줄 빈칸.

**국비 · 수강 동기 / 수료 후 계획** — 과정명 + 희망 분야 문장 + [수료 후 지원할 직무] 빈칸.

**주거 · 거주 사유(펼쳤을 때만)** — {무주택·1인 가구·소득 문장} + "[현재 거주 형태: 예) 보증금 500 / 월세 50]".

### 6-2. 기본 초안 품질 기준 (규칙·AI 공통 검사 `checkDraft()`)
통과 못 하면 AI 초안은 버리고 규칙 초안을 쓴다. 규칙 초안이 실패하면 테스트에서 잡는다.

1. 공고 고유 정보 1개 이상 포함(`title` 또는 `org` 또는 요약에서 뽑은 지원 내용·업무 키워드).
2. 상황 문장 ≤ 2개, 모두 §4 변환 결과에서 온 것.
3. 금지 패턴 0개: `?`, `입니까|습니까\?`, `→`, `예\)|아니오`(예시 괄호 `예)` 는 빈칸 안에서만 허용), `인터뷰`, `제 상황\(`, `판단했습니다`, `기여하겠습니다`로만 끝나는 문장.
4. 빈칸 `[ ]` 1~3개, 모두 "예)" 예시 포함.
5. 길이 120~400자, 2~5문장, 습니다체.
6. 공고·답에 없는 숫자·자격·기관명 없음(AI 출력은 숫자가 공고 원문에 있는지 대조).

### 6-3. `/api/prep` 입력 변경
- 지금: `인터뷰 답: 지금 서울에 살고 있습니까? → yes / …`
- 바꿈: `내 사실: 서울에 살고 있습니다 / 현재 일자리를 찾고 있습니다` (§4 결과만), `공고 유형: job_event`, `대상 판정: warn(중장년)`, `필요한 초안: [30초 자기소개, 현장 질문 3개]`.
- block 이면 호출하지 않음. warn 이면 사용자가 요청할 때만.
- 출력은 기존 JSON 형식 유지, `checkDraft()` 통과분만 교체.

## 6-4. 제목 정리 규칙 (화면·초안 공통)
실제 제목 `77_(일자리 수요데이) 중장년 취업이음+ (주)면사랑 구인구직 만남의 날 면접 공동행사` 처럼 앞에 회차 번호·행사 시리즈명이 붙는다.
- 표시용 `cleanTitle`: 앞 `^\d+_` 제거, 맨 앞 괄호 묶음 `(일자리 수요데이)`는 부제(meta 줄)로 이동. 원제목은 원문 링크·복사 텍스트에만 유지.
- 초안에 넣을 때는 `cleanTitle` 을 「」로 감싼다. 40자 넘으면 회사명·행사 종류만 남긴 짧은 이름(「(주)면사랑 면접 공동행사」) 사용.
- 기관이 `고용24 채용행사` 처럼 출처명이면 "○○의 공고에 지원합니다"에 쓰지 않는다(지금 초안의 "고용24 채용행사의 「…」" 오류). 제목 안 회사명(`(주)…`)이 있으면 그 회사를 주어로 쓴다.

## 8. 구현 범위 메모 (나중에, 지금은 하지 않음)

- 새 함수: `lib/prep/profile.ts`(`buildProfile`, `factSentences`), `lib/prep/kind.ts`(`prepKind`), `lib/prep/target.ts`(`targetCheck`), `lib/prep/draft.ts`(유형별 틀 + `checkDraft`).
- `ruleBasedPlan` 은 위 함수를 조합하는 얇은 함수로. `fit/check` 대신 `rows: {cond, mine, verdict}[]`.
