# 찾아줄게 UX 레퍼런스와 화면별 제안

작성: 2026-11-21 / Claude(시장조사·UX 스레드). 코드는 수정하지 않았고, 개발 스레드가 골라 반영할 수 있도록 화면 단위로 정리했다.
출처 표기: **[공식]** 서비스 자체 도움말·문서, **[연구]** 논문·독립 조사, **[기사]** 언론·리뷰 사이트, **[홍보]** 벤더 자료·보도자료·자사 블로그(수치는 참고만).

## 2. 화면별 제안 (와이어프레임 텍스트)

현재 화면: `/`(홈) → `/play`(질문) → `/result`(결과) → `/alerts`(알림·반복 리서치 현황). 아래는 이 흐름을 유지한 채 바꾸는 것만 적었다. 우선순위 **P0**(발표 전 필수), **P1**(있으면 점수 상승), **P2**(시간 남으면).

### 2-1. 홈 `/` — 약속을 한 문장으로 (P0)

```
┌──────────────────────────────┐
│ 찾아줄게                     │
│                              │
│ 질문 6개에 답하면,            │
│ 주거·채용·지원금 공고를        │
│ 매일 대신 찾아서 알려줄게.     │
│                              │
│  지금 보고 있는 출처 7곳       │
│  [LH] [마이홈] [잡알리오] ...  │
│  어제 새로 올라온 공고 12건    │  ← 서버 scan 결과 숫자(없으면 숨김)
│                              │
│   [ 30초 만에 시작하기 ]       │
│   이미 조건이 있어요 → 알림함   │
└──────────────────────────────┘
```
- "추천"이 아니라 "매일 대신 찾아본다"를 첫 문장에 둔다(교차 평가에서 정책 추천과 혼동된 지점).
- 출처 로고 칩은 실제 연결된 어댑터만 표시. 샘플 폴백 중인 출처는 회색 + "예시".

### 2-2. 질문 `/play` — 갈리는 숫자를 보이게 (P0)

```
┌──────────────────────────────┐
│ ← 3 / 6          남은 공고 41 │
│ ▓▓▓▓▓▓▓▓░░░░░░░░             │
│                              │
│   혼자 살고 있거나            │
│   독립할 예정이에요?          │
│                              │
│   예면 23개, 아니오면 18개 남아요│  ← 각 답변 시 잔여 후보 수를 미리 계산(getMatches 2회)
│                              │
│  [  예  ]  [ 아니오 ]         │
│        [ 잘 모르겠어요 ]       │
│                              │
│  ─ 방금 −9 (만 34세 이하 아님) │  ← 직전 답 탈락 피드백
└──────────────────────────────┘
```
- 이미 있는 `RemainingGauge`의 −N 팝업을 유지하고, 질문 아래 "약 N개가 갈려요" 한 줄만 추가.
- 6문항 도달 시 바로 결과로 가되, 결과 화면에 "2개 더 답하면 더 정확해요" 버튼(P1).
- "잘 모르겠어요"는 후보를 지우지 않는다는 걸 버튼 아래 작은 글씨로: "모르면 '확인 필요'로 남겨둘게요".

### 2-3. 결과 상단 — 조건 한 문장 요약 + 필터 퍼널 (P0)

```
┌──────────────────────────────┐
│ 너의 조건                     │
│ "서울 사는 만 27세 무주택      │
│  1인 가구, 구직 중"            │
│                [수정] [저장됨✓]│
│                              │
│ 전체 58 ─▶ 지역 33 ─▶ 나이 29  │
│      ─▶ 무주택 17 ─▶ 소득 12   │  ← 단계별 남은 수(가로 막대 또는 화살표)
│                              │
│ 딱 맞음 9  ·  확인 필요 3      │
└──────────────────────────────┘
```
- 한 문장 요약은 `Watch.answers`를 규칙 템플릿으로 조립(AI 불필요, 키 없을 때도 동작). AI가 있으면 말투만 다듬기.
- 퍼널은 답변 순서대로 `remaining` 값을 저장해 두면 그릴 수 있다(추가 API 없음).
- Zillow의 저장 검색 이름처럼 이 문장이 알림함·푸시·주간 리포트의 제목으로 계속 쓰인다.

### 2-4. 결과 하단 — 병목 조건 완화 제안 (P1, 차별 포인트)

```
┌──────────────────────────────┐
│ 💡 조건 하나만 풀면           │
│                              │
│ 지역 '서울' → '수도권'   +7개 │ [넓혀보기]
│ 소득 조건 '모름'으로 두기  +4개│ [넓혀보기]
│ 관심분야에 '국비과정' 추가 +6개│ [추가]
│                              │
│ ※ 넓힌 조건으로 늘어난 공고엔  │
│   "조건 완화" 라벨을 붙여요    │
└──────────────────────────────┘
```
- 계산: 답변 하나씩 뺀(또는 '모름'으로 바꾼) 상태로 `getMatches` 재실행 → 증가 수 상위 3개. 엔진 순수 함수라 서버 비용 없음.
- Airbnb 방식처럼 늘어난 공고 카드에 "무엇이 안 맞는지" 라벨 필수("지역 다름: 경기").
- 결과가 3개 이하일 때는 이 카드를 결과 목록 **위**로 올린다(0건 막다른 길 방지).
- 개발 스레드 구현 타입과 대응: `lib/insight/types.ts`의 `FunnelReport.bottleneck`(gain 최대), `scarce`(통과 ≤3 또는 통과율 <5%), `FilterStep.aloneRemoved`(그 조건 하나로 탈락한 수).

#### 2-4-1. 타협 불가 여부는 병목일 때만 묻는다 (사용자 요청 반영)

사용자 예시: 거리로 100개, 나이로 80개가 남는데 금액 조건 하나 때문에 1개만 남는 경우. 처음부터 "이 조건 꼭 지켜야 해요?"를 모든 질문마다 물으면 일반 리서치 사이트처럼 무거워진다. 그래서 **병목으로 확인된 조건 하나에 대해서만, 결과 화면에서 한 번** 묻는다.

```
┌──────────────────────────────┐
│ 소득 조건 때문에 1건만 남았어요 │
│                              │
│ 거리 ▓▓▓▓▓▓▓▓▓▓ 100           │
│ 나이 ▓▓▓▓▓▓▓▓   80            │
│ 소득 ▏           1  ← 병목    │  ← aloneRemoved 막대, 병목만 강조색
│                              │
│ 이 조건은 꼭 지켜야 하나요?     │
│ [ 꼭 지켜야 해요 ]             │  → FilterStep.hard=true, 다음 병목 후보 제시
│ [ 넓혀서 볼래요 (+23건) ]       │  → 해당 답변을 '모름'으로, 늘어난 카드에 "조건 완화" 라벨
└──────────────────────────────┘
```
- "꼭 지켜야 해요"를 고르면 그 조건은 이후 완화 제안·주간 리포트 제안에서 빠진다(hard는 `Watch`에 저장 필요).
- 병목이 없으면(gain 0) 이 카드 자체를 숨긴다. 질문 단계는 예/아니오/모름 3버튼 그대로 유지.

#### 2-4-2. 자료가 적거나 조사 실패일 때 비중 표시 (사용자 요청 반영)

```
조사한 공고 58건 중 너에게 맞는 공고 4건 (6.9%)
 주거 2/11 · 채용 1/10 · 지원금 1/10 · 국비 0/9
 ⚠ 2개 출처는 오늘 응답이 없어 예시 데이터로 대체했어요
```
- 통과율 = `passed / total`, 분야별은 `byDomain`. 실패 출처는 `ScanSnapshot.failedSources`.
- "0건"과 "조사 실패"를 구분해서 보여 준다. 출처가 실패했는데 0건이라고 하면 신뢰를 잃는다.

### 2-5. 저장·알림 설정 — 즉시/주간 선택 (P0)

```
┌──────────────────────────────┐
│ 이 조건으로 매일 찾아볼게      │
│ "서울 · 27세 · 무주택 · 구직"  │
│                              │
│ 언제 알려줄까?                │
│ ◉ 딱 맞는 새 공고·마감 D-3만   │
│   바로 (주 최대 3건)           │
│ ○ 일요일 저녁 주간 리포트로만   │
│                              │
│ 매일 오전 9시에 7곳을 확인해요  │
│ [ 알림 켜고 저장 ]             │
└──────────────────────────────┘
```
- 푸시 권한 요청은 이 버튼을 누른 뒤에만(앱 진입 즉시 요청 금지).
- "매일 오전 9시"는 `vercel.json` cron과 일치해야 한다.

### 2-6. 알림함 `/alerts` — 반복 리서치가 일하는 모습 (P0)

```
┌──────────────────────────────┐
│ 반복 리서치 현황               │
│ 마지막 조사  오늘 09:00        │
│ 다음 조사    내일 09:00        │
│ 확인한 출처  7곳 (2곳 예시데이터)│
│                              │
│ 조사 기록                     │
│ 11/21  새 3 · 마감임박 1  ▸    │
│ 11/20  새 0                   │
│ 11/19  새 5 · 마감임박 2  ▸    │
│                              │
│ 이번 주 알림 2/3건 사용        │
│ [지금 다시 조사하기]           │
└──────────────────────────────┘
```
- "새 0" 날도 기록에 남긴다. 아무것도 없을 때 "확인했는데 없었다"를 보여 주는 게 대신 찾아본다는 약속의 증거.
- 발표 시연: 어제 날짜로 저장된 조건 → [지금 다시 조사하기] → 새 공고 푸시 도착. 이 장면 하나가 교차 평가의 "백그라운드 반복 탐색 부재" 지적에 대한 답.

### 2-7. 주간 리포트 (P1)

```
┌──────────────────────────────┐
│ 11월 3주차 리포트              │
│ "서울 · 27세 · 무주택 · 구직"  │
│                              │
│ 이번 주 7곳에서 찾은 새 공고 8 │
│  주거 2 · 채용 4 · 지원금 2    │
│ 마감된 공고 3 (놓친 것 1) ⚠    │
│ 다음 주 마감 예정 2            │
│   · 행복주택 ○○ D-4           │
│   · 청년월세 지원 D-6          │
│                              │
│ 조건 점검: 지역을 넓히면 +7    │  ← 2-4 완화 제안 재사용
│ [이번 주 공고 전체 보기]        │
└──────────────────────────────┘
```
- 수치는 서버 scan 기록 집계(분야별 새 공고 수, 만료 수, 다음 주 마감). 매주 1회 푸시 1건 = 알림 상한에 포함.
