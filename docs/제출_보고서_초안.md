## 01 문제 정의 (1장)
**장면**: 경기 북부에 사는 취업 준비 청년은 임대주택 모집, 공공기관 인턴, 청년 지원금을 각각 다른 사이트에서 날마다 확인한다. 조건이 맞는 공고는 드물고, 언제 올라올지 모르니 확인을 멈출 수 없다. 놓친 공고는 마감 뒤에야 안다. (팀원 직접 경험)

**근거(정부 원문 확인)** — 2024 청년 삶 실태조사(만 19~34세 15,098명)
- 필요한 정책 분야: 주거 45.7%, 일자리 33.5%
- 공공임대 거주 의향 71.7% vs 실제 거주 경험 7.0% (※ 격차의 원인이 공고 누락이라고 단정하지 않는다)
- 취업 정보 경로 중 공공기관 이용 24.4%
- 보조 근거(민간 조사, 2026.1, 청년 521명): 본인이 정책 대상인지 불명확 50.5%

**기존 서비스의 한계**: 분야별로 나뉘어 있다 — 혜택(정부24 혜택알리미·카카오뱅크 정부지원금), 주거(LH 청약플러스·마이홈 알림), 채용(잡코리아·사람인·잡알리오 알림). 분야마다 조건을 따로 입력해야 하고, 공개 사용자 자료에서는 필터 부정확·반복·무관 공고·추천 결과와 실제 자격의 차이가 확인된다(정량 누락률 자료는 없음). 한 조건으로 여러 분야를 함께 지켜보는 기능은 조사 범위에서 확인하지 못했다.

## 03 AI를 활용한 해결 방안 (1장)
**해결 방안 개요**: 공고 수집(공공 API) → AI가 자격요건 문장을 조건(나이·지역·무주택·소득·취업상태)으로 구조화 → 게임으로 받은 답과 코드로 판정 → 결과·병목 분석 → 저장한 조건으로 매일 재조회해 변화만 알림

**왜 AI여야 하는가**: 공고마다 자격요건 문장 형식이 제각각이다("만 19세 이상 39세 이하 무주택 세대구성원으로서 해당 세대의 월평균소득이 전년도 도시근로자 100% 이하인 자" 등). 출처가 늘수록 규칙을 사람이 일일이 만들 수 없어, 문장을 조건으로 바꾸는 단계에 AI가 필요하다.

**AI 적용 지점**
| 지점 | 모델 | 키 없거나 실패 시 |
|---|---|---|
| 자격요건 문장 → 조건 구조화(신뢰도 포함) | Claude Sonnet | 규칙 기반 추출 |
| 질문 문장을 자연스럽게 | Claude Haiku | 기본 문장 |
| 매칭 이유 설명 | Claude Haiku | 규칙 기반 설명 |

**오류·불확실성 대응**: 판정·병목 계산·새 공고 비교는 코드가 한다. AI가 해석한 조건에는 "AI 해석" 배지와 원문 문장을 함께 보여 주고, 신뢰도가 낮거나 사용자가 "모름"으로 답한 조건은 합격으로 단정하지 않고 "확인 필요"로 남긴다. 최종 자격은 원문에서 확인하도록 링크한다.

# AI 활용내역 (제출 페이지 입력칸, 3,000자 이내)

① 활용 AI 모델·도구
[서비스] Anthropic Claude API — Sonnet(모델 ID `[배포 시 확정]`, 공고 원문의 자격요건 문장을 나이·지역·무주택·소득·취업상태 조건으로 구조화하고 신뢰도 표시), Haiku(질문 문장 다듬기, 매칭 이유 설명). 키가 없거나 호출이 실패하면 규칙 기반 처리로 자동 전환.
[개발] Claude Code(화면·서버·데이터 어댑터·테스트 작성과 통합), OpenAI Codex(필터 병목 분석 알고리즘 초안, 코드·보안 리뷰, 아이디어·시장조사 교차 평가), ChatGPT 심층 리서치(청년 주거·교통·구직·알바 고민 조사 → 문제 후보 선정에만 사용, 소개서 수치는 정부 원문으로 재확인), Exa 웹 검색(경쟁 서비스 기능·2024 청년 삶 실태조사 원문 확인 → 01·06장).

② AI 활용 범위와 팀의 기여
- 문제 정의: 팀원이 직접 겪은 불편("조건 맞는 공고가 언제 올라오고 내려갈지 몰라 여러 사이트를 매번 확인")에서 출발했다. 아이디어 후보 9개를 만든 쪽이 아닌 다른 AI가 냉정하게 채점하는 교차 평가 규칙을 세워 선정했고, 최종 방향(게임식 조건 입력 + 분야 횡단 반복 조사·알림)은 팀이 결정했다.
- 설계: 서비스 구조, 데이터 모델, "판정은 코드·해석은 AI" 원칙, 개인정보 최소화(예·아니오 범주값만 저장)는 팀이 정했다.
- 구현: 코드 초안은 AI가 작성했다. 팀은 병렬 작업 범위(파일 경계·인터페이스)를 정하고, 결과를 통합·테스트하며 수정 방향을 지시했다. 필터 병목 알고리즘은 Codex 초안을 Claude가 검토·수정했고, 서버 코드는 Codex 코드·보안 리뷰 후 소유자 토큰 해시 검증, 푸시 구독 호스트 제한, 예약 실행 인증, 저장 목록 상한·삭제 기능을 반영했다.
- 팀이 화면을 직접 점검하다 같은 답에서 "바로 신청 0건"이 나오는 판정 오류를 발견했고, AI와 함께 원인 3가지(관심 분야, 나이 하한, 취업상태 추론)를 고쳤다.
- 서비스 안의 AI: 공고마다 다른 자격요건 문장을 조건으로 바꾸는 일에만 AI를 쓰고, 사용자 답과의 판정, 필터 병목 계산, 새 공고·마감 변경 비교는 코드가 수행한다.

③ API·외부 데이터·오픈소스
공공데이터포털 LH 분양임대공고문·마이홈 공공주택 모집공고(주거), 잡알리오 공공기관 채용정보(채용), 행정안전부 공공서비스(혜택) 정보·온통청년(정책·지원금), 고용24 훈련과정·국가자격 시험일정(교육·자격). 연결 전 출처는 실제 공개 공고를 바탕으로 만든 예시 데이터로 대체하고 화면에 "샘플 데이터"로 표시한다. 선택 기능(기본 꺼짐): SH 공식 RSS(제목·링크·게시일만), Tavily·Exa 웹 검색(공공기관 도메인 한정, 제목·링크·요약 200자). 오픈소스: Next.js, React, Tailwind CSS, web-push, Vitest. 상세 출처·라이선스는 소개서 별첨 표에 기재.

④ 검증 및 한계 대응
- 2026.11.21 로컬 검증에서 자동 테스트 76개(질문 엔진, 출처 어댑터, 필터 병목, 알림 판정, 마감 변경·임박 감지, 중복 제거, 보안 유틸, 게임→결과→저장→반복 조사 통합 흐름)와 빌드·타입·린트 검사 통과.
- AI가 해석한 조건에는 "AI 해석" 배지와 원문 문장을 함께 표시하고, 신뢰도가 낮거나 "모름"으로 답한 조건은 "확인 필요"로 남긴다. 최종 자격은 공고 원문 확인을 안내한다.
- Claude에는 공고 원문 또는 공고 메타데이터·질문 조건값만 보내며, 사용자 이름·연락처나 자유입력은 보내지 않는다. 이름·연락처는 수집하지 않고, 범주형 답변과 푸시 구독 정보는 최대 60일 저장하며 알림함에서 삭제할 수 있다.
- 연결되지 않은 출처는 "예시 데이터"로 구분해 0건과 조사 실패를 혼동하지 않게 했다.
- 남은 한계: 공고 삭제 감지 미구현, 알바는 합법 공개 API가 없어 예시 데이터만 사용.
