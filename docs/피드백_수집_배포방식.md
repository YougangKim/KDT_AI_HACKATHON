# 사용자 피드백 수집 배포 방식 (조사·추천)

> 출처: Codex 조사 `.ai-sync/tasks/20261123T160651-codex/result.md` (2026-11-24, 공식 문서 확인). Claude 검토: 현재 web/package.json에 분석 도구 없음 확인, 결론 유지. 대량 트래픽 비용 최소화는 별도 스레드(트래픽 몰릴 때 AI 의존 줄이기) 범위.

## 결론

- 추천: **Vercel Web Analytics(Hobby, 월 5만 이벤트) + Tally 무료 설문(결과 화면 버튼, path·ref 숨은 필드) + 모집 채널별 `?ref=` 링크**. 코드 변경 1~3파일, 비용 0원.
- 보류: PostHog·Clarity(세션 리플레이 사전 동의·마스킹 검증 부담), 앱 내 Upstash 피드백 API(심사 이후 지속 운영 시).
- 필수: 푸터에 개인정보 처리방침(수집 항목·목적·보유기간·수탁자·국외 저장·거부 방법), 의견 칸에 '개인정보 적지 마세요'.

## 개인정보 처리방침에서 최소한 다룰 내용

개인정보보호법 제30조는 처리 목적·보유기간·파기·수탁자·정보주체 권리·자동수집 장치 등을 처리방침에 포함하고 쉽게 공개하도록 요구한다. 국외 이전·보관에는 이전 근거와 관련 사항도 필요하다 ([법 제30조](https://www.law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078922), [개인정보위 국외 이전 안내](https://pipc.go.kr/np/default/page.do?mCode=D060040000)).

따라서 최소한 다음을 푸터에서 바로 접근 가능하게 공개하는 편이 안전하다.

- 수집 항목, 목적, 보유기간과 파기 방법
- Vercel·Upstash·Google·Tally 등 실제 사용하는 수탁자와 저장 국가
- 쿠키·분석·세션리플레이 도구명, 수집 정보, 거부 방법
- 열람·삭제 요청 연락처
- 한줄 의견에 이름·연락처·건강·경제상황 등 개인정보를 적지 말라는 안내

단순한 쿠키 없는 익명 집계는 별도 동의 필요성이 낮을 수 있지만, **세션리플레이는 사전 동의를 받는 구성이 가장 보수적**이다.

## 2~3일 최소 추천 조합

**Vercel Web Analytics + Tally + 모집 채널별 링크**를 추천한다.

1. Vercel Web Analytics로 방문자·페이지·유입 채널을 자동 집계한다.
2. 결과 화면에 Tally 피드백 버튼을 넣고 `path`, `source`를 URL 파라미터나 숨은 필드로 넘긴다.
3. 모집 채널마다 `?ref=university`, `?ref=openchat`처럼 구분한다.
4. 개인정보 처리방침과 짧은 조사 안내를 푸터 및 폼 첫 화면에 둔다.
5. 앱 내 Upstash 피드백 API는 심사 이후 지속 운영이 필요할 때 구현한다.

이 조합은 로그인 없는 앱에 적합하고, 코드 변경이 작으면서 방문량과 정성 피드백을 함께 확보한다. Clarity·PostHog는 세션리플레이 동의와 마스킹 검증 때문에 이번 2~3일 최소 범위에서는 제외하는 편이 낫다.

모집은 청년정책·취업 준비 오픈채팅, 대학 에브리타임/학과 커뮤니티, 부트캠프·해커톤 동료 채널 등에 “5분 사용 후 익명 설문” 형태로 게시할 수 있다. 이는 채널 예시이며, 각 커뮤니티의 홍보 규칙과 운영자 허가를 먼저 확인해야 한다.

## 핵심 지표 5개

1. **고유 방문자 수**
2. **서비스 시작률**: 시작 버튼 클릭을 직접 측정하기 어렵다면 `/play` 방문 ÷ 홈 방문
3. **결과 도달률**: `/result` 방문 ÷ `/play` 방문
4. **피드백 응답률**: 설문 제출 수 ÷ 결과 페이지 방문자 수
5. **평균 만족도와 재사용 의향**: 5점 척도 평균 및 긍정 응답 비율

로그인 없는 도구의 방문자 수는 정확한 개인 수가 아니라 브라우저·일별 해시 기반의 추정치임을 보고서에 명시해야 한다.
