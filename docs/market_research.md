## 1. 요약

- **사실**: 정책·지원금 맞춤 추천과 알림은 이미 강하다. 정부24 혜택알리미는 2025년 말 약 6,000종으로 확대됐고 은행·웰로 등에서도 가입된다. 카카오뱅크는 새 지원금·마감 임박 알림까지 준다. 주거(LH·마이홈)와 채용(사람인·잡코리아·잡알리오)도 **각자** 조건 알림을 준다.
- **사실**: 확인한 범위에서 주거·채용·알바·지원금·국비과정·자격증을 **하나의 조건 프로필로 반복 조사해 새 공고·마감 임박만** 알리는 국내외 서비스는 찾지 못했다(확신도 중간, "없다"의 증명은 아님).
- **추론**: 차별점은 "맞춤 추천"이 아니라 **분야 횡단 공고 모니터링 + 새 공고·마감 변화만 선별 + 왜 맞는지 근거 표시**다. "정책 추천 앱"으로 소개하는 순간 웰로·온통청년·혜택알리미와 겹친다.
- **주의**: "분야 횡단 서비스 없음"은 공개 자료 기준이며 경쟁 앱 내부 기능을 직접 써 보고 확인한 것은 아니다(8절 검증 항목).
- **권고**: 발표·화면 문구를 "질문으로 조건을 저장하면, 연결에 성공한 출처를 매일 다시 조회한다(예시 데이터 출처는 따로 표시)"로 고정하고, 시연은 "어제 저장한 조건 → 오늘 새 공고 푸시"로 한다. 사용자 불만은 정량 근거가 약하므로 "알림 누락이 심하다" 같은 주장은 쓰지 않는다.

발표에 쓸 핵심 숫자 3개(권고):
1. **주거 45.7%·일자리 33.5%**가 청년이 가장 필요로 하는 정책 → 청년이 주거와 일자리 정책을 각각 높은 우선순위로 꼽았다는 근거. 한 사람이 두 분야를 동시에 원한다는 근거는 아니므로 단일 프로필 수요는 별도 검증 필요.
2. **공공임대 거주 의향 71.7% vs 경험 7.0%** → 의향과 경험의 격차는 확인되지만, 공고를 놓친 것이 원인인지는 이 조사로 판단할 수 없다(공급 부족·자격·지역 불일치도 가능). 발표에서는 "격차"까지만 말한다.
3. **본인이 정책 대상인지 모름 50.5%**(민간 521명) → 질문으로 조건을 정해 주는 근거. 반드시 "민간 조사"라고 밝힌다.

쓰면 안 되는 것:
- 2024 정부 조사와 2026 민간 조사를 섞어 "정부 조사 결과 84.5%가 모른다"고 쓰기.
- 웰로 소개 페이지의 "국민 75%가 정책을 모르거나 절차가 복잡해 신청하지 않는다" 문구: 원조사·표본이 없다 [홍보] [웰로 회사 소개](https://www.wello.info/).
- "구직자는 평균 N개 사이트를 본다": 신뢰할 원조사를 찾지 못했다.

## 5. 시사점 (추론)

1. **분야를 쪼개 보면 다 있다.** 각 분야 1위 서비스가 이미 알림을 준다. 그래서 사용자 고통은 "알림이 없다"가 아니라 "알림 앱이 분야마다 따로 있고, 조건을 앱마다 다시 넣어야 한다"로 정의해야 한다.
2. **혜택알리미가 가장 큰 반박 근거다.** 심사위원이 "정부24에 이미 있다"고 물으면, 혜택알리미는 공공 혜택 단위이고 마이뉴스는 LH·마이홈 모집공고, 잡알리오 채용, 국비과정·자격증 일정 같은 **기한이 있는 개별 공고**를 다룬다는 점으로 답한다.
3. **신뢰가 핵심 품질이다.** 기존 서비스 불만이 "안 맞는 공고"와 "최종 자격 아님"에 몰려 있으므로, 결과마다 원문 자격조건과 "확인 필요"를 보여 주는 현재 구조(Match.unknowns, 저신뢰 표시)가 차별 근거가 된다.
4. **알림은 적을수록 좋다.** 반복 알림 불만과 알림 피로 근거가 있으므로 "새 공고·마감 임박만, 주 최대 N건"을 기능이자 메시지로 쓴다(`docs/ux_reference.md` 원칙 4·5).

## 6. 위험과 반론

- **실데이터 부족**: 알바는 공개 API가 없어 샘플이고, 키가 없으면 분야별 샘플로 폴백한다. 분야 횡단이 차별점인데 시연에서 실데이터 분야가 2~3개뿐이면 차별점이 약해진다. → 실데이터가 되는 분야와 샘플 분야를 화면에 구분 표시.
- **"없다"의 증명 불가**: 분야 횡단 서비스 부재는 확인 못함 수준이다. 발표에서 "국내 최초" 표현 금지.
- **웰로·혜택알리미의 확장 가능성**: 큰 서비스가 채용·주거 공고를 붙이면 차별점이 사라진다. → 반론 대응은 "개별 공고 반복 조사 + 짧은 질문 조건 생성"이라는 조합과 구현 완성도.
- **수치 출처 혼동**: 정부 통계와 민간 설문을 섞지 말 것(3절).
- **리뷰 근거 약함**: 불만 근거의 다수가 낮음~중간 확신도.

## 7. 권고 (개발·발표 반영)

1. 한 줄 소개: "질문 몇 개로 조건을 정하면, 주거·채용·지원금·국비과정 공고를 매일 다시 조회해 처음 보는 공고만 알려준다." (현재 서버 조사는 새 공고 ID만 감지한다. 마감 변경·임박의 서버 푸시는 구현 후에만 문구에 넣을 것)
2. 경쟁 비교 슬라이드: 2절 기능 공백 매트릭스를 단순화해 "분야별 앱 N개 + 조건 N번 입력 vs 마이뉴스 1번".
3. 근거 슬라이드: 주거 45.7%·일자리 33.5%(정부), 공공임대 의향 71.7% vs 경험 7.0%(정부), 대상 여부 모름 50.5%(민간, 표기).
4. 시연 순서: 질문 6개 → 결과(조건 한 문장 + 퍼널) → 저장 → 알림함 조사 기록 → [지금 다시 조사] → 푸시 도착.
5. 예상 질문 대비: "정부24 혜택알리미와 뭐가 다르냐", "카카오뱅크도 마감 알림 주는데", "알바 데이터는 진짜냐", "공고 자격 판정이 틀리면".
   Codex 교차 검토(`.ai-sync/tasks/20261121T004024-codex/result.md`)가 추가로 지적한 미대비 질문 3개:
   - "자격 구조가 다른 주거·채용·지원금에서 한 프로필이 정말 재사용되나, 결국 분야별 질문을 다시 받는 것 아닌가?" → 답: 공통 속성(나이·지역·무주택·소득·취업상태)으로 대부분 걸러지고, 분야 고유 조건은 '확인 필요'로 남긴다는 걸 결과 화면에서 보여 준다.
   - "7개 출처 중 오늘 실제 API로 조회된 곳은 몇 곳인가?" → 답: 알림함에 출처별 실데이터/예시 상태와 마지막 조회 시각 표시(ScanSnapshot.failedSources).
   - "공고 수정·삭제·마감 연장·중복·잘못 구조화된 자격조건은?" → 답: 원문 링크와 원문 자격 문장을 항상 함께 보여 주고 최종 판단은 원문 기준임을 명시. 수정·중복 감지는 확장 계획으로 정직하게 말한다.
