# 민간(또는 민간 공고를 담은) API 조사

작성: 2026-11-21 23:10 (Claude 조사 스레드). 기준: 마감 11/23(월) 17:00 전에 **개인이 키를 받아** 붙일 수 있고, 약관상 앱에 노출해도 되며, 입상에 실제로 보탬이 되는가. 크롤링·비공식 내부 API는 대회 규정상 실격 위험이라 전부 제외.

출처는 각 항목에 단 공식 페이지. 승인 소요 시간 중 "추정"이라고 쓴 것은 공식 수치가 없어 판단한 값이다.

## 1. 청약홈 분양정보 조회 서비스 — 채택 추천

- 출처: https://www.data.go.kr/data/15098547/openapi.do , 기술문서 https://www.reb.or.kr/reb/na/ntt/selectNttInfo.do?bbsId=1268&mi=10251&nttSn=79889 (26.01.29 수정판)
- **발급**: data.go.kr 활용신청, 개발단계 **자동승인**, 개발계정 트래픽 40,000. 무료, 이용허락범위 제한 없음. 이미 data.go.kr 키가 있으므로 같은 계정에서 활용신청만 추가하면 됨(자동승인 후 키 동기화까지 보통 수 분~1시간, 추정).
- **약관**: 이용허락범위 제한 없음 → 앱 노출 가능. 공고 원문 URL(`PBLANC_URL`, applyhome.co.kr) 링크로 보내면 됨.
- **제공 범위**(오퍼레이션 6개, `https://api.odcloud.kr/api/ApplyhomeInfoDetailSvc/v1/...`):
  - `getAPTLttotPblancDetail`: APT 분양(민영·국민 구분 `HOUSE_DTL_SECD_NM`, 신혼희망타운, 민간사전청약)
  - `getUrbtyOfctlLttotPblancDetail`: 오피스텔·도시형·민간임대·생활숙박시설
  - `getRemndrLttotPblancDetail`: APT 무순위/잔여세대
  - 각 주택형별 상세(분양가 `LTTOT_TOP_AMOUNT`, 만원 단위)
  - (2024.02 추가) 공공지원 민간임대, 임의공급 분양정보
  - 주요 필드: 주택명, 공급위치, 지역코드, 모집공고일, 특별공급·1순위·2순위 접수일, 당첨자 발표일, 계약기간, 입주예정월, 총공급세대수
- **생기는 기능**:
  - 주거 결과에 "민간 분양·민간임대" 공고가 처음으로 들어감. 지금 LH·마이홈·SH는 공공 위주라 "청년이 실제로 보는 청약 공고 절반이 빠졌다"는 심사 반박을 막음.
  - 특히 **공공지원 민간임대**(청년 특공 비중 큼)와 **무순위/잔여세대**(청약통장 없이 가능한 경우 많음)는 아키네이터 질문("청약통장 있어요?")과 바로 연결됨.
  - 접수 시작·마감일이 구조화돼 있어 기존 D-3 알림(`lib/server/changes.ts`)에 그대로 태울 수 있음.
- **연동 난이도: 하**. `gov24.ts`와 같은 odcloud 형식(`page`, `perPage`, `cond[...]`, `serviceKey`). 어댑터 1개 + 매핑 + 테스트로 3~4시간(추정).
- **주의**:
  - 자격 판정용 필드(소득·자산·나이)는 없음. 공고문 PDF에만 있어서 엔진은 지역·접수기간·주택구분 정도만 하드 판정하고 나머지는 "확인 필요"로 둬야 함(현재 `lenient()` 방침과 같음).
  - 날짜 필드 형식이 오퍼레이션마다 다름(APT는 `YYYY-MM-DD`, 공공지원 민간임대·임의공급은 `YYYYMMDD`).
  - LH 공고(신혼희망타운 등)가 LH API와 겹침 → 기존 `dedupe.ts`로 공식 API 우선 제거.
  - 엄밀히는 공공기관(한국부동산원)이 제공하는 API지만 **내용은 민간 시행사 분양 공고**라 이번 조사 목적에 맞음.

## 2. 사람인 채용정보 API — 지금 신청, 승인되면 켜기

- 출처: https://oapi.saramin.co.kr/introduce , /guide/info , /guide/job-search , /caution , /join
- **발급**: 이용신청(이름·소속·전화·서비스 URL·이용목적 50자 이상) → **사람인 담당자 심사 승인** → 승인 메일 후 앱 등록 → access-key. 공식 승인 기간 표기 없음. 학교/전공으로도 신청 가능한 양식이라 개인 신청 자체는 막혀 있지 않음.
- **마감 전 가능성: 낮음~중간(추정)**. 지금이 토요일 밤이라 심사는 빨라야 월요일 오전. 월요일 오전에 오면 반나절 안에 켤 수 있음. 오지 않을 가능성을 기본으로 계획해야 함.
- **약관**(/caution): 일 500회, 사람인 제공 표기 의무, 재판매·이용료 부과·이용자에게 대가 받기 금지, 출처 사칭 금지. 무료 해커톤 앱 노출은 허용 범위.
- **API**: `GET https://oapi.saramin.co.kr/job-search?access-key=...` JSON. 키워드·지역(`loc_cd`)·직무·고용형태(`job_type`, 인턴 포함)·학력(`edu_lv`)·마감일·정렬 필터, 1회 최대 110건. 응답에 공고 URL·진행 여부·게시/마감일.
- **생기는 기능**: 지금 채용은 잡알리오(공공기관) + 고용24(예정) 뿐 → 민간 기업 신입·인턴 공고가 들어가 "공공기관만 나온다"는 약점이 사라짐. 마감일이 있어 D-3 알림에도 연결됨.
- **연동 난이도: 하**. REST 1개. 일 500회 제한이라 사용자 요청마다 호출하지 말고 서버 스케줄러가 조건별로 모아 캐시해야 함.
- **권장 처리**: 사용자가 오늘 밤 바로 신청(서비스 URL은 Vercel 주소). 어댑터는 `SH_RSS_ENABLED`처럼 기본 OFF 플래그로 미리 만들어 두고, 키가 오면 켬. 오지 않으면 보고서에 "신청 완료, 승인 대기"로만 적음.

## 3. ODsay 대중교통 API — 보류(여유 있을 때만)

- 출처: https://lab.odsay.com/doc/totalPolicy , https://lab.odsay.com/contact/contact , 포럼 https://lab.odsay.com/community/boardView?seq=645
- 발급: 회원가입 → 앱 등록 즉시 키(Basic: 개인·학생 무료). 서버 플랫폼은 공인 IP 등록 필요(Vercel은 IP 고정이 안 돼 **URI 플랫폼 + 클라이언트 호출**이 현실적, 그러면 키가 노출됨).
- 한도: 운영정책 표는 **일 30회**, 2025.07 포럼 관리자 답변은 "6개월, 일 1,000회"로 상충. 30회면 데모용으로만 가능.
- 기능: 주거 공고 카드에 "내 학교/직장까지 대중교통 n분". 청년 주거 선택에서 실제로 중요한 기준이긴 하지만 공고 좌표가 없어(주소만) 지오코딩 API가 하나 더 필요 → 마감 대비 효과가 작음.
- 판정: **이번 마감에는 넣지 않는 것을 권장**. 1·2번이 끝나고 시간이 남을 때만.

## 제외 근거 상세

- **잡코리아**: https://www.jobkorea.co.kr/network/Popup_Xml.asp 약관 제5조 4항 "대학, 대학교, 공공기관이 아닌 개인, 일반 기업이거나 이용목적이 프로젝트, 개인 사용 … 인 경우 승낙하지 아니한다". 사업자번호 입력란도 있음. 해커톤 개인 프로젝트는 명시적 불승인 대상.
- **알바몬·알바천국**: 공개 개발자 API 없음. 알바몬 개인정보처리방침에 "XML 채용정보신청" 항목이 잡코리아와 동일하게 있음(기관 신청 경로, 같은 거절 조건으로 판단). 검색되는 연동 수단은 Apify 스크래퍼·BeautifulSoup 크롤러뿐 → 규정 위반.
- **원티드**: https://openapi.wanted.jobs/apply/ 사업자등록번호·회사명 필수, "3 영업일 이내" → 개인 불가, 월요일 신청해도 마감 후.
- **직방·다방·피터팬**: 공식 공개 API 없음. 개발자 글은 전부 브라우저 네트워크 탭으로 내부 API를 찾아 호출하는 방식(사실상 크롤링). 제휴는 기업 협의 필요.

## Codex 병행 조사에서 추가된 후보 (2026-11-21 23:03, Codex 응답 요약·Claude 미검증)

- **Tavily Search**: 즉시 발급, 월 1,000 credits 무료, 제목·URL·스니펫 표시·저장 허용(Codex 확인). 앱에는 이미 `lib/sources/websearch.ts`(기본 OFF)로 들어가 있어 새 작업 없음. 키만 넣으면 됨.
- **Exa Search**: 월 $10 무료 크레딧. 재표시·장기 저장 범위가 불명확 → 공식 도메인 제목·URL·짧은 근거만 쓰는 지금 방식 유지.
- **네이버 검색 API**: 저장·가공·AI 입력 제한, 신규 발급 경로 이관 문제 → 반복 조사·알림 용도에 부적합, 제외.
- **카카오 로컬**: 지도 실시간 표시는 가능하나 응답·식별키 저장 금지 → 공고 캐시와 맞지 않음, 제외(통근 기능을 한다면 화면에서 즉시 호출만 가능).
- Codex도 사람인을 "즉시 신청, 필수 데이터원으로 의존 금지"로 판정해 이 문서 결론과 같음.

### 네이버 검색 API
- 출처: NAVER API 서비스 이용약관(2026-10-07 개정) https://developers.naver.com/products/terms/ , 개정 공지 https://developers.naver.com/notice/article/33400
- 특약 2.2: 결과는 독립적으로, 가공 없이 노출해야 함. 순위·내용 수정·변조 금지, 앞뒤에 다른 내용 삽입 금지. 원본 출처 표시·링크 의무.
- 특약 2.3: 데이터(가공물·파생물 포함)를 복사·저장·캐싱하는 행위 금지(2.4 예외만), **데이터를 AI에 입력하거나 학습·개선·평가·노출에 활용하는 행위 금지**, 광고·수익 금지.
- 특약 2.4: 임시 캐싱만 허용. 기기 보관은 24시간 또는 새 질의 시까지, 서버 보관은 "이력 조회 목적" 최대 21일, 개인화 목적은 24시간.
- 부칙 제2조: 2026-07-30 24:00부터 개발자센터에서 Search API **신규 신청 중단**(NAVER API HUB로 이관). 지금 새로 받으려면 NCP API HUB 별도 절차·약관.
- 이 앱에 걸리는 점: ① 공고 후보를 엔진(조건 필터)으로 걸러 순위를 바꿔 보여주는 것 자체가 2.2 "가공 없이 노출" 위반 소지 ② AI 조건 해석(`lib/ai`)에 넣으면 2.3 정면 위반 ③ seenIds·매일 비교용 저장은 21일 이력 조회 예외로 보기 어려움(추정) ④ 신규 발급 경로가 개발자센터에서 막힘.
- 문제없이 쓰는 방법: 사실상 없음. 쓰더라도 "네이버 검색결과" 별도 탭에 원본 그대로·링크만, AI·필터·알림 미연결. 이 앱 핵심 기능과 연결이 안 되므로 넣을 가치 없음.

  - 참고: 2025-07 답변(https://devtalk.kakao.com/t/api/145284)은 "식별키만 저장도 제재"라고 했으나 2026년 답변에서 ID 저장 허용으로 바뀜 → 해석이 흔들리는 영역
- 이 앱에 걸리는 점: 로컬 API로 얻을 정보는 "공고 주소 → 좌표"(통근 시간·지도) 정도인데, 좌표를 공고와 함께 저장·캐시할 수 없고 AI에 넣을 수 없음. 매일 스캔·알림에는 못 씀.
- 문제없이 쓰는 방법: 결과 카드에서 사용자가 누를 때만 화면에서 실시간 호출해 지도·위치를 보여주고 저장하지 않음. 가능은 하지만 마감 전 우선순위 낮음(공고 원문 링크로 충분).

### 대안
- 주소 → 좌표가 꼭 필요하면 공공 지오코딩(국토교통부 브이월드, 행정안전부 도로명주소 좌표 API)이 저장 제한이 덜함(약관 미확인, 추정). 지금 마감 범위에서는 넣지 않는 것을 권장.

## 사용자가 할 일 (순서대로)

1. data.go.kr에서 "한국부동산원_청약홈 분양정보 조회 서비스" 활용신청(자동승인). 기존 키 그대로 쓰면 됨.
2. https://oapi.saramin.co.kr/join 에서 사람인 API 이용신청(이용목적 50자 이상, 서비스 URL은 배포 주소). 승인 메일이 오면 앱 등록 후 access-key를 `config/api_keys.csv`에.
3. 구현은 실데이터 구현 스레드에서: 청약홈 어댑터 먼저, 사람인 어댑터는 기본 OFF로.
