# 세입자 하자·수선 협의 에이전트 — 입출력 상세 설계 (데모 v0)

- 작성: 2026-11-21 02:35 KST
- 한 줄 정의: 세입자가 찍은 하자 사진과 짧은 설명을, **수리업자가 바로 견적을 낼 수 있는 견적요청서**와 **임대인에게 보낼 증빙 협의문**으로 바꿔 주는 AI 에이전트.
- 원칙: AI는 원인·책임을 확정하지 않는다("진단"이 아니라 "관찰기록"). 금액은 업자만 정한다.

## 1. 화면 흐름 (5단계, 한 페이지 스텝퍼)

| 단계 | 화면 | 사용자 입력 | 시스템 출력 |
|---|---|---|---|
| 1 | 집 정보 | 주소(검색), 임대 형태(월세/전세), 입주일, 건물 층·호(선택) | 주소 정규화, 건축물대장 요약(준공연도·용도·구조) |
| 2 | 하자 올리기 | 사진 1~5장, 한 줄 설명, 발견일 | 업로드 미리보기 |
| 3 | AI 분석 | 없음(대기) | 하자 항목 카드 목록(부위·증상·크기 추정·긴급도·권장 공종), 각 필드에 상태 배지 |
| 4 | 확인 질문 | AI가 낸 2~3개 질문에 답(선택형 우선) + 카드 값 수정 | 상태 배지가 "사용자 확인"으로 바뀜 |
| 5 | 문서 받기 | 받을 문서 선택, 희망 수리일 | PDF 3종 미리보기·다운로드, 공유 링크, 주변 업체 5곳 |


## 3. AI 출력 스키마 (LLM 1회 호출, JSON 강제)

모든 값은 `{ "value": ..., "status": "observed|inferred|user_confirmed|pro_verified", "evidence": "photo#2" }` 형태.

```json
{
  "defects": [
    {
      "id": "D1",
      "room": "욕실",
      "location": "천장 중앙, 환풍기 옆",
      "symptom": "물 얼룩과 물방울 맺힘",
      "size": "약 40cm x 30cm",
      "spreadRisk": "높음 | 보통 | 낮음",
      "urgency": "즉시 | 1주 내 | 여유",
      "trade": "누수·설비",
      "possibleCauses": ["윗층 배관", "욕실 방수층"],
      "cause": "확인 필요",
      "photoRefs": [1, 2]
    }
  ],
  "missingQuestions": [
    {"id": "Q1", "text": "물이 계속 떨어지나요, 샤워할 때만인가요?", "options": ["계속", "윗집 사용 시", "모름"]},
    {"id": "Q2", "text": "윗집이 있나요?", "options": ["있음", "없음(최상층)", "모름"]}
  ],
  "safetyFlag": "전기 근처 누수면 차단기 확인 안내 | null"
}
```

### 프롬프트 규칙 (시스템 프롬프트 핵심)
1. 사진에서 보이는 것만 `observed`. 보이지 않는 추정은 `inferred`.
2. `cause`는 항상 "확인 필요". 가능성은 `possibleCauses`에만.
3. 임대인/임차인 책임, 비용 금액은 절대 출력하지 않는다.
4. 견적에 필요한데 사진으로 알 수 없는 정보만 `missingQuestions`로(최대 3개, 선택지 포함).
5. 사진이 하자와 무관하거나 흐리면 `defects: []`와 재촬영 안내를 반환.

## 4. 출력 문서 3종 (같은 데이터로 생성)

### 4-1. 하자 관찰기록 (세입자 보관용)
- 머리: 주소, 임대 형태, 입주일, 작성일, 건물 준공연도(건축물대장)
- 표: 항목ID | 방·부위 | 증상 | 크기 | 확대 가능성 | 긴급도 | 사진 | 상태 배지
- 꼬리: "본 기록은 사진 관찰 기록이며 원인과 책임을 판정하지 않습니다."

### 4-2. 수리 견적요청서 (업자용)
- 작업 위치: 주소, 층, 엘리베이터 유무, 주차 가능 여부(질문으로 수집)
- 작업 항목: 공종 | 부위 | 증상 | 크기 | 사진
- 견적 요청 항목(빈칸): 출장·점검비 | 자재비 | 시공비 | 예상 작업시간 | 방문 가능일
- 희망 수리일, 연락 방법(데모는 공유 링크)

### 4-3. 임대인 수리 협의 요청문
- 사실관계: "2026-11-15 욕실 천장에서 누수를 발견했습니다."
- 첨부 사진 목록, 관찰기록 요약 표
- 요청: "점검 및 수리 일정 협의를 요청드립니다. 회신 희망일: 2026-11-24"
- 참고(고정 문구): 「민법」 제623조 임대인의 수선 의무 조문 원문만 인용, 해석 문장 없음
- 감정 표현·비난 표현 금지, 책임 단정 금지

## 5. 외부 데이터

| 용도 | API | 승인 | 데모 처리 |
|---|---|---|---|
| 주소 정규화 | 행안부 도로명주소 검색 API | 즉시 | 데모는 샘플 주소 3개 고정 |
| 건물 정보 | 건축HUB 건축물대장 표제부 | data.go.kr 자동승인, 개발 1만 건 | 샘플 응답 JSON 하드코딩 |
| 주변 업체 | 소상공인 상가(상권)정보 반경 조회 | 자동승인, 개발 1만 건 | 업종 코드별 샘플 5곳 하드코딩 |

데모 단계에서는 키 없이 돌아가도록 샘플 데이터를 쓰고, 본 개발에서 실제 API로 바꾼다.

## 6. 오류·예외 처리

| 상황 | 처리 |
|---|---|
| 사진 없음 | 다음 단계 버튼 비활성 |
| 하자 아닌 사진, 흐린 사진 | "하자 부위를 가까이 다시 찍어 주세요" + 촬영 가이드 |
| AI 응답 JSON 깨짐 | 1회 재시도 후 실패 시 수동 입력 폼 |
| 전기·가스 관련 | 안전 배너("차단기·밸브 먼저 잠그고 전문가 점검") |
| 사용자가 값 수정 | 상태 배지 `user_confirmed`로 변경, 문서에 반영 |

## 7. 데모 시나리오 (심사 시연 90초)
1. 샘플 주소 선택 → 건물 1994년 준공 표시
2. 욕실 천장 누수 사진 2장 + "물이 떨어져요"
3. AI 카드 2개(천장 얼룩, 실리콘 곰팡이) + 질문 2개 답변
4. PDF 3종 미리보기 → 주변 누수·설비 업체 5곳
